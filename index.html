Ostracon

從 git history 重建程式碼的決策演化史：一段程式碼何時誕生、被哪幾次改動 重塑、每次的理由是什麼、以及哪些做法試過又被推翻。 全程零 LLM——這些畫面上的每一個字都來自 AST 解析、雜湊比對與逐字引文。

意圖欄的空白是真實的觀測值，不是還沒載入。理由是稀有的：三個語料裡 說得出專屬理由的改動都不到 0.3%。這個工具的價值不在於把空格填滿。

Featured excavation ／ 精選案例

packages/reactivity/src/Dep.ts:hasBit

用位元旗標加速依賴的重新追蹤——當天引入，當天撤掉。 Ostracon 只憑結構就找得到它：這個宣告誕生又消亡，而且移除掉的內容 與當初加入的逐字相同（A 級確證，git 層面可獨立驗證）。

  1. 2021-07-16 perf(reactivity): use bitwise dep markers to optimize re-tracking (#4017)
  2. 2021-07-16 refactor: reduce bundle size

兩行都是 commit 主旨的逐字引用，不是抽取出來的理由——這兩顆 commit 都沒有因果標記，所以它們的意圖欄是空的。這條的故事由結構說完，不靠文字。 點進去看完整時間軸 →

「被推翻的做法」只計 A 級——結構上可獨立驗證（git revert，或移除的與加入的 逐字相同）。C 級是「僅生命週期符合、未經證實」，不當成結論呈現。 每個語料都釘在固定的 commit，是快照不是即時服務。原始碼與方法論： github.com/lduo8438-max/ostracon
